# Swift 6 Rules

All targets use `.swiftLanguageMode(.v6)`. Strict concurrency is always on.

## Container isolation

`Container` is an `actor`. This means:

- All `register` and `resolve` calls are `async` — no `@unchecked Sendable` workarounds.
- Stored factories and instances are actor-isolated; no external mutation is possible without `await`.
- Do NOT convert `Container` to a class with a `Mutex` or `OSAllocatedUnfairLock` to avoid `await`. The actor approach works on iOS 13+ and needs no `import Synchronization`.

## Injectable types and Sendable

Katana supports both `Sendable` and non-`Sendable` injectables. The scope determines which path is taken.

### Singleton scope → `Sendable` required

The container holds a cached reference AND shares it with callers — two live references to the same object. Swift 6 requires `Sendable` here to prevent data races.

| Type | Sendable? | Notes |
|------|-----------|-------|
| `@Observable final class` | ✅ implicitly | Observation system provides isolation |
| `@MainActor final class` | ✅ implicitly | Global actor provides isolation |
| `final class` with `let`-only storage | ✅ explicit conformance | Add `: Sendable` |
| `struct` with Sendable fields | ✅ implicitly | Value type, copied |
| Plain `class` with `var` state | ❌ | Must be transient or refactored |

### Transient scope → non-`Sendable` OK via `sending`

The container creates a fresh instance and transfers exclusive ownership to the caller using `sending` (SE-0430, Swift 6.0+). The compiler guarantees no concurrent access because the container discards its reference before the value reaches the caller.

```swift
// Container resolves and sends — it no longer holds the reference
func resolve<T: Injectable>(_ type: T.Type) async -> sending T
```

Non-Sendable types that make sense as transient:
- Per-request context objects
- Mutable builder/coordinator types
- UIKit view controllers (when not shared)

## Factory closures

Registration takes a `@Sendable` factory closure:

```swift
await container.register(NetworkService.self) { container in
    await NetworkService(config: container.resolve(Config.self))
}
```

The `@Sendable` requirement is enforced at the call site — do not use `@unchecked Sendable` factories.

## Macro-generated code

The `resolve(from:)` method generated by `@Injectable` is `nonisolated` on the conforming type and `async` because it calls into the actor. It must not be annotated `@MainActor` — callers decide isolation.

```swift
// ✅ Correct generated signature
static func resolve(from container: Container) async -> Self

// ❌ Never generate this
@MainActor static func resolve(from container: Container) async -> Self
```

## Tests

Use `swift test` which runs under strict concurrency. Tests that resolve from a container must be `async`. Use Swift Testing (`@Test`) for new tests; XCTest is acceptable for macro expansion tests (`assertMacroExpansion` is synchronous and not actor-aware).
